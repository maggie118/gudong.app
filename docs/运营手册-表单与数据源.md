# Gudong 运营手册（完整版）

更新：2026-11-14

这份手册回答两件事：**网站的数据从哪来、改哪里会让什么变**；以及**每天 / 每月 / 每季度具体做什么**。

## 一、先看这张地图

```
                    ┌─────────────────────────────────────────────┐
   卖家填表  ───────▶│  Google 主表（唯一内容数据源）                │
   你审核后搬行      │  1bXToBUVn9T1R6dcImOvQAlh2arXdDx4n1mto…    │
                    │  ├ 第 2 张表单回复 ← 藏品提交表单             │
                    │  ├ 第 1 张表单回复 ← 卖家入驻表单             │
                    │  ├ sellers   正式卖家档案（网站读这个）       │
                    │  ├ items     正式藏品表（网站读这个）         │
                    │  └ revenue_monthly  月度收入（只内部用）      │
                    └───────────────┬─────────────────────────────┘
                                    │ 构建时拉公开 CSV（无需密钥）
                                    ▼
                    npm run build（Vercel 每次部署自动跑）
                                    │
                                    ▼
                    静态站 gudong.app（首页 / items / sellers / pricing …）

   买家在站上的一切行为 ──▶ Cloudflare D1（gudong-data）
                            buyers / favorites / follows / inquiries /
                            inquiry_clicks / messages / push_subs / mail_subs …
                                    │ 经 Worker gudong-data-api（x-gudong-key）
                                    ▼
                            藏家后台 /seller.html#token=…（看板 + 询价）

   收入记录 ──▶ 主表 revenue_monthly ──▶ 季度快照脚本 ──▶ data/snapshots/*.md|csv
```

一句话：**内容（藏品、藏家）在 Google 表格里，行为数据（买家）在 D1 里，钱在 revenue_monthly 里，三者只在 `seller_id` 这一层有关联。**

## 二、三种数据的边界（这条先记住，比操作更重要）

| 数据 | 存在哪 | 谁能看到 | 绝不能做什么 |
|---|---|---|---|
| 藏品 / 藏家资料 | Google 表格 `items` `sellers` | 全站公开（藏馆页、藏品页） | 不要在站上写鉴定结论、不要写"捡漏" |
| 买家行为（收藏、关注、询价、点击） | Cloudflare D1 | 只有你 + 该藏家看自己的汇总 | 绝不把买家姓名 / 邮箱 / 号码给任何藏家 |
| 收入 | Google 表格 `revenue_monthly` | 只有你 | 不进任何藏家可见页面，也不和买家按人绑定 |

藏家能看到的边界（已经写进页面）：关注数、收藏数、咨询数、最常被收藏 top5，加上自己收到的询价内容。**看不到**：买家是谁、平台总收入、自己的付费状态和年费到期日。

## 三、新卖家入驻：从表单到拿到链接

### 第 1 步：他填表

发给他：**卖家入驻申请**
`https://docs.google.com/forms/d/e/1FAIpQLSeu3dk4sJ8dmJW1DQh-KC2dcm7GzN4zj2TnQGieo6S1USblrw/viewform`

必填：中文展馆名、英文展馆名、邮箱、从业年份、藏馆简介。其余（卖家编号、WhatsApp、是否申请私家藏馆、图片/资料链接）可空。

站上也有入口：首页卖家区「提交入驻申请」、`/pricing` 的申请席位按钮。

### 第 2 步：你审核

提交会落到主表 **「第 1 张表单回复」** 页签。审核时看三件事：

1. 是不是真的在做古董生意（有无实体、有无既往记录）；
2. 简介有没有夸大或虚假来源（有就退回，不要自己改）；
3. WhatsApp 号是否可直接联系。

### 第 3 步：把这一行搬进 `sellers` 页签

在 `sellers` 页签新增一行，16 列按这个填（**列顺序不要改，改了构建就读不到**）：

| 列 | 字段 | 怎么填 |
|---|---|---|
| A | `seller_id` | **你的内部编号，一旦定了永不改**。格式 `姓-名缩写`，如 `Lim-KW`、`Ng-CY`。它是藏品归属、藏馆页地址、后台令牌、收入关联的主键 |
| B | `display_zh` | 中文展馆名 |
| C | `display_en` | 英文展馆名 |
| D | `since_year` | 从业起始年份，四位数字，如 `1998` |
| E | `intro_zh` | 中文简介（2–4 句，写器物品类与来源地，不写鉴定结论） |
| F | `intro_en` | 英文简介（与中文同义，不要机翻味） |
| G | `title_focus` | 主攻品类，如 `清代瓷器` / `东南亚高古` |
| H | `gallery` | 只写 `TRUE` 或 `FALSE`。**只有 TRUE 才会生成私家藏馆页**，也才可能进付费档 |
| I | `gallery_started_at` | 付费开馆那天，`YYYY-MM-DD`。填了它，从当天起自动进「今日发现」免费 7 天 |
| J | `gallery_expires_at` | 年费到期日，`YYYY-MM-DD`（一般 = 开馆日 +1 年） |
| K | `founding_no` | 创始席号，三位（`001`…）。同一编号不能重复，构建会把重复的规范掉 |
| L | `page_url` | 留空，构建时自动生成 `/sellers/seller-xxx` |
| M | `wa_username` | WhatsApp 用户名（wa.me 链接用） |
| N | `wa_phone` | WhatsApp 号码，带国家码，只留数字，如 `6591234567` |
| O | `status` | `active` = 在线；其他值 = 不展示 |
| P | `finds_bonus_until` | 续费曝光到期日，见第五节。没有就留空 |

**不信 gallery 的三种情况**：免费入驻（`gallery=FALSE`，只有卖家名和藏品，没有藏馆页，也没有数据看板）；付费藏馆（`TRUE`）；撤馆（`gallery` 改 `FALSE`，下次构建藏馆页即下架，但 `items` 里他的藏品还在，要一起处理）。

### 第 4 步：发布，然后发链接

改完表格告诉我「发布」（或按第七节自己发）。构建会：

- 生成藏馆页 `sellers/seller-<id>.html` → 线上 `/sellers/seller-<id>`
- 生成该馆二维码 `assets/qr/seller-<id>-antiques.{svg,png}`
- 重建 `/sellers` 目录页

然后把**两样东西**发给他：

1. 公开藏馆页 `https://www.gudong.app/sellers/seller-<id>`
2. （仅 `gallery=TRUE`）藏家后台私密链接 `https://www.gudong.app/seller.html#token=…`

后台链接怎么来：`node scripts/generate-seller-inbox-links.js`，产物写进 `藏家收件箱链接（勿外发）.txt`（已在 `.gitignore` 里，别提交）。链接用 `CHAT_REPLY_SECRET` 签名，**有效期 365 天**，到期重新生成。一个链接只能看自己家，看不了别家。

## 四、新藏品上架：从表单到页面

### 第 1 步：他填表

**藏品提交**
`https://docs.google.com/forms/d/e/1FAIpQLSeQOE9oBw3bleAwFcUZMA2IhiNrO3Ax8p7Iat1z8sgL4XZdiA/viewform`

必填：卖家编号、中文名称、年代、图片文件名或 Drive 链接、是否申请「今日发现」曝光。

> Google 表单不能传图。让他按 `assets/images/<卖家目录>/<文件名>.jpg` 命名后把文件名填进来，或者直接把原图发你 WhatsApp，你放进去并回填文件名。

### 第 2 步：图先到位

图片放进仓库 `assets/images/<卖家目录>/`，命名与 `img_file` 完全一致。要求：器物真实颜色与形状不能改（可以做曝光、裁边、去背景），一张主图够用。

### 第 3 步：搬进 `items` 页签

| 字段 | 说明 |
|---|---|
| `item_id` | **页面地址就是它**（`/items/item-lim-05`），上架后永不改；改一次等于换链接，已收藏的买家会失效。沿用卖家编号 + 序号 |
| `title_zh` / `title_en` | 器物名，中文按行内叫法，英文准确对译 |
| `era_zh` / `era_en` | 年代，如 `清乾隆` / `Qing, Qianlong` |
| `category` | 统一用中文品类词，别混英文（历史数据里混过） |
| `dimensions` | 尺寸，如 `H 32 cm` |
| `has_surface_wear` / `has_surface_damage` | `TRUE/FALSE`，如实填，页面会展示 |
| `price_type` / `price_display_zh` / `price_display_en` | 价格方式与展示文案；不公开价格就写「价格面议 / Enquire」 |
| `img_file` | 图片文件名，与仓库路径一致，**没图不生成页面** |
| `seller_id` | 必须与 `sellers.A` 完全一致，否则这件藏品挂不到藏馆页，也无法归属到有数据 |
| `is_today_finds` | 是否进「今日发现」 |
| `is_new_listing` | 是否标「刚刚上新」 |
| `status` | `active` 才在线 |
| `reason_zh` / `reason_en` | 卡片上的一句购买理由（不带鉴定结论） |
| `listed_at` | 上架日 `YYYY-MM-DD`。**不填 `expiry_date` 时，构建按 `listed_at` + 6 个月自动下架** |
| `expiry_date` | 想指定展示期就填，否则留空 |
| `previous_price` / `fixed_price` | 数字，用于价格变动展示 |

### 第 4 步：发布

同第七节。构建会新建 `items/item-<id>.html`、更新 `data/listings.json`，并刷 sitemap。

### 上架前自查（4 项，30 秒能查完）

- [ ] `item_id` 全站唯一、且没改过
- [ ] `seller_id` 能在 `sellers` 里对上
- [ ] `img_file` 的图真的在仓库里
- [ ] 文案没有鉴定结论、没有「捡漏 / 漏可捡」

## 五、私家藏馆 S$588 与「今日发现」曝光

单价：S$588/年（早鸟价，全价 S$1,288），含 2 件专业上架名额。

### 开通

1. 收款；
2. `sellers` 页签：`gallery` 改 `TRUE`，`gallery_started_at` 填收款当天，`gallery_expires_at` = 当天 +1 年；
3. 发布 → 藏馆页上线，同时生成后台链接；
4. 从开馆日起，他全店藏品**自动进「今日发现」7 天**（例：11-12 开馆 → 展示到 11-18，11-19 自动退出，不用你手动撤）。

### 续费曝光

`finds_bonus_until` 写一个日期就行，构建按「今天 ≤ 该日期」判定在曝光位，过期自动失效。日期别手算：

```bash
node scripts/finds-renew.js Yap-JM 7      # 续 7 天，打印该填的日期
node scripts/finds-renew.js Ng-CY 14 --apply   # 14 天，并同时写进仓库备份 CSV
```

续费起点不浪费天数：免费窗口没结束就接窗口次日，已在续费期就接原到期日。

### 单件加买曝光（可选）

`items.exposure_until` 单件到期日，优先于卖家级窗口；`items.exposure_tier` 档位，数字越大排得越前。

### 到期与提醒

- 构建日志会打印「开馆免费 7 天窗口」「续费到期提醒：X（剩 N 天）」；
- `data/expiry-report.json` 里 `expiring_soon_finds` 是 7 天内到期的名单，可直接拿去 WhatsApp 提醒；
- 到期不续费：什么都不用做，下次构建自动退出曝光位（藏馆页和藏品页仍在线，直到 `gallery_expires_at`）。

## 六、买家侧到底是怎么运作的

### 登录与身份

- 买家点「Google 登录」→ 写 D1 `buyers`（email / name / source / google_sub / consent_at），本机存 `gudong_buyer`；
- 不留邮箱的人也能用站：本机生成匿名身份，收藏、关注照样记，只是没有邮箱。

### WhatsApp 前的那层窗（留邮箱可跳过）

- **已登录 / 本机已有身份的人点 WhatsApp，不弹窗，直接打开对话**；
- 只有「从没登录 + 本机无身份」的人才会看到弹层：留邮箱可以，但**可以点「不用了，直接打开 WhatsApp」跳过**——跳过也会记一次匿名点击（`inquiry_clicks`），只是不写 `inquiries`。

### 三条数据流

| 行为 | 写哪张表 | 藏家能不能看到 |
|---|---|---|
| 点 WhatsApp | `inquiry_clicks`（可匿名） | 只看到「咨询次数」这个数 |
| 留了邮箱/号码并发询价 | `inquiries`（含状态 new/contacted/closed） | 看到询价内容和联系方式（这是他自己该回的） |
| 收藏 / 关注 | `favorites` / `follows` | 只看到汇总数字和 top5 |

### 藏家后台（一个链接看两件事）

`/seller.html#token=…` → 跳到 `/seller-inbox`：

- 上半：藏馆数据（关注 / 收藏 / 咨询 + 近 30 天增量 + 最常被收藏 top5）；
- 下半：询价列表，可标「已联络 / 关闭」；
- 页面底部一行固定免责：**咨询次数＝买家点了 WhatsApp 的次数，实际成交平台看不到；数据匿名汇总，不含买家姓名、邮箱或号码**。

### 你能在后台做什么

- 看某个藏家这季度的数：用他的令牌打开他的后台，或跑一次季度快照看全站；
- 不要私自导出买家邮箱列表发给藏家——这是 PDPA 红线，也是当初不做「按人关联」的原因。

## 七、发布：三种情况，别混

| 你改了什么 | 怎么发 | 生效时间 |
|---|---|---|
| **只改 Google 表格**（新增卖家、上架、改曝光日、填收入） | 什么都不用做，等每天 **16:00（新加坡）** 的自动重建；想立刻生效就告诉我「发布」 | 自动 ≤ 1 天；手动约 3 分钟 |
| **改了仓库代码 / 页面文案** | `npm run build` → commit → `git push origin HEAD:main`（Vercel 自动部署）；必要时再打一次 Deploy Hook | 约 3 分钟 |
| **改了 Cloudflare Worker**（`cloudflare/worker.js`） | **必须手动**：把全文另存为 UTF-8 无 BOM 的 txt → Cloudflare 后台 `gudong-data-api` → 编辑代码 → 全选粘贴 → 部署 | 约 1 分钟 |

> Worker 不能用本机脚本自动部署：本机没有 `CLOUDFLARE_API_TOKEN`，`cloudflare/deploy.mjs` 会生成新密钥，把 Vercel 上的 `GUDONG_DATA_KEY` 打乱，导致全站买家数据写入失败。

发布后怎么验收（30 秒）：
1. 打开 `/sellers/seller-<id>`，看藏馆页有没有新藏品；
2. 打开 `/items/item-<id>`，看图和价；
3. 打开 `/seller.html#token=…`，看数据块有没有数字。

## 八、每月 / 每季度要做的两件事

### 每月：填收入

主表 **`revenue_monthly`** 页签，9 列：

`month | stream | orders | revenue | refunds | new_customers | repeat_customers | notes | seller_id`

- `month` 写 `2026-11` 这种文本；
- `stream` 只用五个值：`上架` / `藏馆` / `Signature` / `附加服务` / `续展`；
- `revenue` 只写数字（588，不要 `S$`、不要千分位）；`refunds` 单独记，不冲减收入；
- `seller_id` 可选，藏馆/续展这类能落到具体馆的行填上。

### 每季度：出一份快照

```bash
node scripts/quarterly-snapshot.js --quarter 2026-Q4 --input snapshot.json
```

产出 `data/snapshots/2026-Q4-buyer-data.{md,csv,json}`，md 里同时有买家侧和收入侧，附口径与限制。取数方式见 `docs/QUARTERLY_SNAPSHOT.md`。

## 九、Airtable 现在还有没有用？

**结论：核心业务已经完全不依赖它了，但代码里还留着三处「可选兜底 / 历史遗留」。**

已经离开 Airtable 的：

| 东西 | 现在在哪 |
|---|---|
| 藏品 / 卖家（网站内容） | Google 主表 `items` `sellers`（`scripts/sheets-source.js` 默认指向它） |
| 买家名单 / 询价 | D1 `buyers` `inquiries` |
| 收藏 / 关注 / 消息 / 推送订阅 | D1 `favorites` `follows` `messages` `push_subs` |
| 收入 | Google 主表 `revenue_monthly` |

还挂着 Airtable 的（不影响你日常运营，但建议清掉）：

| 位置 | 它读 Airtable 做什么 | 影响 |
|---|---|---|
| `api/chat.js`（AI 客服） | 回答时查一次上架表（价格、在售） | 这是唯一还在真实调用 Airtable 的地方。额度耗尽或 token 失效时客服会退化（答不出具体在售信息），不影响站和其它功能 |
| `api/lead.js` | D1 写失败时兜底写 Airtable `buyer_leads` | 只是 failover，正常情况下 0 次调用 |
| `api/airtable-proxy.js` | 只读代理 | 前端已 0 次调用，属于可删文件 |
| `scripts/send-new-items-push.js` | 上新推送脚本从 Airtable 拉 items | 现在没在用（推送走 Worker `/push`） |
| `scripts/refresh-listings.js` | 有 Airtable 分支 | 只有 Google 表格读不到时才走，正常不走 |

**要不要现在彻底退役？** 建议做，但要按顺序：① 先把 `api/chat.js` 的取数改成读构建产物 `data/listings.json`（不再依赖任何表格 API）；② 删 `api/airtable-proxy.js` 和 `lead.js` 的兜底；③ 停掉 Airtable 上的表。第 ① 步是唯一有实际收益的（避免以后额度再爆时客服降级），要不要我改？

## 十、常见故障：先查这几条

| 现象 | 最可能的原因 | 怎么修 |
|---|---|---|
| 改了表格，网站没变 | 静态站要重新构建 | 等 16:00 自动构建，或让我发布 |
| 构建报「sheet not readable」 | 主表共享被改成了「仅自己」 | 共享 → 通用访问「知道链接的任何人（查看者）」 |
| 新藏品不显示 | `img_file` 图不在仓库 / `seller_id` 对不上 / `status` 不是 active / 已过期 | 四项逐个核 |
| 藏馆页 404 | `gallery` 不是 `TRUE`，或 `status` 不是 `active` | 改回 TRUE 再发布 |
| 后台看板没数字 | 链接里没带 token，或 token 过期（1 年） | 重新生成链接；确认 `CHAT_REPLY_SECRET` ≥ 32 字节 |
| 后台显示「还没有买家询价」 | 确实没人询价（跳过 WhatsApp 的人只记点击，不进询价） | 看「咨询次数」那个数 |
| 买家数据写不进 | Worker 密钥与 `GUDONG_DATA_KEY` 不一致（常见于误跑了 `deploy.mjs`） | 在 Cloudflare 核对 `INTERNAL_KEY`，或在 Vercel 同步 `GUDONG_DATA_KEY` |
| 曝光位该退没退 | 那天还没构建 | 等构建或手动发布 |

D1 控制台（手动查数据 / 删数据）：
`https://dash.cloudflare.com/b1b46e9369291ee99b61663ff325785f/workers/d1/databases/e3a0fbe9-4844-4f48-9fae-4834dc23de5b/console`
（表：`buyers` `favorites` `follows` `inquiries` `inquiry_clicks` `messages` `push_subs` `push_sent` `push_runs` `mail_subs` `saves`）

## 十一、脚本速查

```bash
npm run build                              # 全套构建（Vercel 自动跑的就是这个）
node scripts/finds-renew.js <seller_id> <天数> [--apply]   # 算续费曝光日期
node scripts/generate-seller-inbox-links.js               # 生成 5 家藏家后台链接
node scripts/quarterly-snapshot.js --quarter 2026-Q4      # 季度快照（含收入）
node scripts/build-sellers.js                             # 只重建藏馆页
node scripts/build-item-pages.js                          # 只重建藏品页
```

相关文档：`docs/ENQUIRY_INBOX.md`（询价收件箱）、`docs/WA_CONTACT_GATE.md`（WhatsApp 留资窗）、`docs/REVENUE_MONTHLY.md`（收入表）、`docs/QUARTERLY_SNAPSHOT.md`（快照口径）、`docs/BUYER_LIST.md`（买家名单）、`docs/DEPLOYMENT.md`（部署细节）。
